## 目标

项目必须遵守目标站点的条款，并以用户拥有或已获授权的内容与素材为前提。

## 技术方案

使用 VitePress 1.6.4。原站本身使用 VitePress，该方案最适合保持 Markdown 内容结构、文档导航、全文搜索、主题切换、文章目录、上一篇/下一篇及编辑链接。

品牌数据集中管理，不在多个组件内重复硬编码。配置至少包含：

- 品牌名称、内容品牌、内容短名称和品牌简称
- 主色
- 正式域名
- GitHub 仓库
- 作者和版权主体
- Logo、favicon、二维码与分享图路径
- SEO 标题、描述和关键词

## 图片迁移与替换

已扫描蓝皮书目录下 35 个目录或章节页面，发现约 234 张独立 PNG、JPG 或 GIF，主要为产品操作截图、流程演示和案例结果图。全部正文图片最终更换。

处理流程：

1. 下载原图到本地作为布局和尺寸校准参考，不在最终站点中热链接原站资源。
2. 建立图片清单，记录章节、出现顺序、用途、原尺寸和建议替换尺寸。
3. 用户分批提供新图片；每张新图与清单编号对应。
4. 逐张替换并检查裁切、清晰度、移动端显示和上下文一致性。
5. 最终版本不得保留原正文图片。

在新素材未到齐之前，项目可以使用原图本地副本完成结构开发和视觉校准，但不能作为最终交付状态。

## 错误与缺失处理

- 图片缺失时不得显示浏览器破损图标。
- 构建阶段输出缺失素材编号和所在页面。
- 内部链接失效视为阻塞交付的问题。
- 外部链接无法访问时记录但不擅自替换资料来源。
- 素材未到齐时明确标记“待素材”，不得宣称最终完成。

## 验收

至少覆盖以下页面与状态：

- 首页桌面端与 390×844 移动端
- 开始阅读、案例集、帮你解决和阅读指南
- 四篇导读
- 含大量图片、表格、代码块和提示框的代表性章节
- 搜索打开、检索与跳转
- 浅色与深色主题
- 交流群弹层
- 桌面与移动导航
- GitHub、贡献和编辑此页链接

验收方法：

1. 在相同视口和相同状态下分别截取原站与复刻站。
2. 并排比较布局、字体、间距、边框、颜色、图片尺寸和交互状态。
3. 修复 P0、P1 和 P2 级差异。
4. 验证所有内部链接、图片引用、控制台错误、构建结果和 SEO 元数据。
5. 生成 `design-qa.md`，仅当最终结果为 `passed` 时交付。
