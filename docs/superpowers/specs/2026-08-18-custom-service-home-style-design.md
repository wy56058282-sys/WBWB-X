# 定制服务页首页化视觉升级设计

## 状态

- 日期：2026-08-18
- 状态：已明确“风格参考而非一比一复刻”，待用户复核
- 适用页面：`/help/`
- 选定方向：首页风格借用版
- 调整范围：在保留现有服务内容、业务规则和 A / C / B 信息结构的前提下，复用首页的品牌基因，并针对服务页的信息密度重新设计比例、间距和模块结构。

## 背景

当前定制服务页已经完成通栏布局、FDE 六宫格、服务目录与转化入口，但整体仍更接近普通文档页。用户希望参考首页的元素与风格，但明确要求“参考风格样式，不是一比一复刻”。

早期视觉对比稿错误使用了 `#c9ff2f` 荧光黄绿色。首页实际强调色是 `--wbx-accent: #32e6b9`，因此正式设计不得沿用该错误颜色。

## 目标

1. 让 `/help/` 与首页在第一眼上属于同一套品牌系统，而不是另起一套营销页视觉。
2. 使用首页已有的主色、黑色描边、圆角主容器、像素图标、黑色信息块和薄荷青绿强调条。
3. 保持现有服务信息、价格、二维码状态、流程、规则和转化边界不变。
4. 保留已确认的响应式合同：桌面三列、平板两列、手机单列。
5. 不通过全局覆盖影响首页、案例页、阅读指南或其他文档页面。
6. 字体家族、色彩、图标库、描边和交互气质与首页同源；字号、字重、间距和模块比例根据服务页重新定标。

## 非目标

- 不修改服务价格、时长、交付物、20 席权益、退款或隐私规则。
- 不新增服务、营销承诺、付款入口、报名入口或测试二维码。
- 不改变商务微信、企业采购渠道和服务付款三条独立路径。
- 不修改全局导航、首页组件、案例页或阅读指南。
- 不部署、不推送远端，也不创建发布版本。

## 视觉基线

正式实现只复用仓库内现有品牌变量：

- 强调色：`var(--wbx-accent)`，浅色主题实际值为 `#32e6b9`。
- 主文字：`var(--wbx-ink)`，浅色主题实际值为 `#0d100d`。
- 页面底色：`var(--wbx-paper)`，浅色主题实际值为 `#f7f8f2`。
- 内容表面：`var(--wbx-surface)`。
- 次级表面：`var(--wbx-hover-surface)`。
- 边界：`var(--wbx-line)`。

`#c9ff2f` 及其近似荧光黄绿色不得出现在定制服务专属组件和样式中。深色主题继续使用 `custom.css` 已定义的品牌变量，不新建另一套硬编码色板。

## 首页风格借用边界

本设计中的“参考首页”不是复制首页组件或逐项照搬数值，而是区分“必须同源的品牌基因”和“必须按服务场景适配的页面参数”。

### 必须同源

- 品牌色变量、正文与像素字体家族。
- HackerNoon Pixel Icon Library。
- 黑色描边、直角按钮、像素标签、绿色图标块和克制硬阴影的视觉气质。
- 清晰的标题—说明—元信息层级，以及可操作元素的 hover / focus 反馈。

### 必须适配

- 服务页 H1 不使用首页大标题的完整尺寸，避免抢占首屏事实和商务入口空间。
- 长页面区块间距、卡片内边距和按钮高度按服务信息密度收束。
- 首页的两列阅读卡、漂浮图标墙和价值条不能原样搬入；只借用其构图方法，服务页继续遵守自己的 `3 / 2 / 1` 决策网格。
- 首页组件的动效仅保留适合服务决策的部分，不复制装饰性漂浮与循环动画。

### 字体

- 正文、标题和按钮全部使用 `var(--wbx-body)`：`"Avenir Next", Avenir, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。
- 英文眉题、编号和元信息使用 `var(--wbx-pixel)`：`"Silkscreen", "SFMono-Regular", Consolas, monospace`。
- 不引入 `Inter`、新字体文件或只在定制服务页存在的字体栈。

### 服务页字体层级

- 首屏 H1：`clamp(44px, 5vw, 56px)`、`font-weight: 800`、`line-height: 1.08`、`letter-spacing: -0.05em`。它保留首页的强标题气质，但低于首页 `52–70px / 850` 的展示尺度。
- 首屏说明：`17px / 520 / 1.75`，低于首页摘要的 `19px / 540 / 1.85`。
- 大区块 H2：`clamp(28px, 3vw, 36px)`、`780 / 1.24`、`letter-spacing: -0.04em`。
- 英文眉题：`11px / 400 / 1.6`、`letter-spacing: 0.08em`，继续使用 `var(--wbx-pixel)`。
- 主按钮：`16px / 720`、桌面 `min-height: 52px`；保留首页直角描边和箭头反馈，不照搬 `62px` 高度。
- 服务卡标题使用 `18px`，说明使用 `14px / 1.55`；方法网格标题使用 `16px`，说明使用 `13px / 1.5`。
- 手机端独立收束字号，不按比例整体缩放桌面稿。

### 服务页间距节奏

- 页面外框：桌面 `20px 24px 0`，手机 `12px 14px 0`。
- 首屏文案区：`48px 30px 44px 48px`；标题前后 `20px / 16px`，CTA 区使用 `24px` 上间距与 `14px` 按钮间距。
- 大区块：桌面 `54px 20px 0`；区块标题与内容间距为 `22px`，标题行主次内容间距为 `32px`。
- 服务卡使用 `20px` 内边距和 `18px` 网格间距；方法矩阵使用 `20px` 内边距。
- 企业采购浅色模块使用 `58px 20px 0` 外间距、`40px` 内边距和 `36px` 双列间距。
- 手机端使用约 `46–48px` 区块间距、`20px` 级卡片内边距和 `30px 20px` 企业模块内边距。

### 图标

- 只使用项目已安装的 `@hackernoon/pixel-icon-library`，以 `.hn` 加具体图标类渲染；不得使用 emoji、Unicode 符号、Lucide 或临时手绘占位。
- 五步实施方法固定映射现有数据：`hn-sitemap`、`hn-filter`、`hn-laptop-code`、`hn-badge-check`、`hn-chart-line`。
- “选择你的下一步”使用 `hn-message-dots`；CTA 箭头使用 `hn-arrow-right`。
- 服务产品卡按语义使用同一图标库，固定映射为：需求诊断 `hn-sitemap`、定制培训 `hn-users`、FDE 现场支持 `hn-badge-check`、项目实施 `hn-laptop-code`、持续支持 `hn-message-dots`。
- 首页式黑色图标块保持 `var(--wbx-accent)` 图标、`#0d100d` 背景和像素化轮廓；浅色服务卡图标块使用 `var(--wbx-accent)` 背景和 `#0d100d` 图标。

## 页面结构与组件

### 1. 首页式首屏容器

将现有需求诊断首屏整理为一个带有首页气质、但按服务决策重新构图的主容器：

- 外层使用 `2px` 主文字色描边、`16px` 圆角、页面表面背景和克制阴影；不照搬首页 `20px` 与 `568px` 高度。
- 左侧保留主标题、说明和“开始需求沟通”按钮。
- 右侧将现有价格、时长、固定交付与商务微信状态组成 `2 × 2` 诊断矩阵，不新增事实或重复文案。
- 诊断矩阵借用首页黑色图标块和绿色强调，但不是漂浮图标墙；第一项使用 `var(--wbx-accent)`，其余使用黑白表面建立节奏。
- 首屏不再追加首页价值条，避免价格和时长重复展示。
- 商务微信未就绪时继续显示不可操作占位；就绪时二维码保持完整静区、正方形比例和准确替代文本。

### 2. FDE 能力区

保持当前三类障碍、三层服务和五步实施方法的内容与顺序：

- 三类障碍使用首页黑色图标卡的视觉语言，薄荷青绿色只用于像素图标或关键编号。
- 三层服务保持独立语义分组，不与障碍卡片套卡片。
- 五步实施方法与“选择你的下一步”组成现有六宫格。
- 六宫格借用首页任务矩阵的线框、像素图标与左右信息关系，但使用服务页自己的 `20px` 内边距和 `16px / 13px` 文本层级。
- 六宫格继续使用桌面 `3` 列、平板 `2` 列、手机 `1` 列。
- “我要学习”和“联系主理人”继续分别链接阅读指南与当前服务申请区。

### 3. 服务产品目录

五类服务改用首页阅读路径卡片的节奏：

- 每张卡只展示现有名称、价格或计价方式、周期和说明。
- 使用清晰边界、`8px` 以内圆角与轻微 hover 位移。
- 卡片借用首页阅读路径的绿色像素图标块、细边界与轻微悬浮反馈，但使用 `20px` 内边距、`64px` 图标块、`18px` 标题和 `14px` 说明层级。
- 桌面 `3` 列、平板 `2` 列、手机 `1` 列。
- 主 CTA 或关键价格可使用薄荷青绿色强调，但不让五张卡全部变成高亮色。

### 4. 企业采购与后续决策区

- 企业版采购使用独立的首页式浅色模块，保留现有二维码、费用边界和 20 席说明。
- “适合带着这些问题来”与“诊断输出”保持并列决策区；桌面可两列，手机单列。
- 沟通流程继续使用一套连续编号，不引入重复视觉编号。
- 服务边界、规则、隐私与相关案例保持低噪声，不把所有长文本强行放进黑色卡片。

### 5. 动效与交互

- 按钮、服务卡和可操作链接借用首页的位移与硬阴影反馈，但缩短位移距离和阴影强度，避免长页面持续跳动。
- 纯信息卡不伪装成可点击元素。
- 所有交互提供高对比度 `:focus-visible`。
- 在 `prefers-reduced-motion: reduce` 下移除非必要位移与过渡。
- 禁用入口不获得可点击外观，也不设置空链接。

## 响应式合同

### `>= 1024px`

- 首屏左右分区，右侧事实与二维码不挤压标题。
- FDE 方法为三列，服务产品最多三列。
- 页面保持约 `1104px` 的现有通栏内容宽度。

### `641px–1023px`

- 首屏信息按可用宽度转为上下或紧凑两列。
- FDE 方法与服务产品均为两列。
- 二维码留在对应语义模块内。

### `<= 640px`

- 所有模块按阅读顺序单列。
- 标题、价格、按钮、二维码和长文案无裁切、重叠或横向滚动。
- 首屏圆角可适当收小，但品牌描边、色彩和信息顺序不变。

## 实现边界

主要改动限制在：

- `docs/.vitepress/theme/ServicePage.vue`
- `docs/.vitepress/theme/service.css`
- `tests/service-page.test.ts`
- `tests/service-page-style.test.ts`

当前工作树中与本设计无关的未提交改动必须原样保留。实现时不执行清理、重置或批量格式化。

## 测试策略

### 组件测试

- 首屏仍包含唯一的价格、时长、固定交付与商务微信状态。
- 五类服务、FDE 三类障碍、三层服务、五步方法与引导卡均完整存在。
- 学习与咨询 CTA 的目标保持正确。
- 商务微信、企业采购和申请入口的就绪状态仍分别受独立配置控制。

### 样式合同测试

- 服务页使用 `var(--wbx-accent)`，且不出现 `#c9ff2f`。
- 服务页使用 `var(--wbx-body)` 与 `var(--wbx-pixel)`，且不出现 `Inter` 或新增字体栈。
- H1、H2、说明、按钮、卡片标题和辅助说明使用本规格定义的服务页适配值，而不是复制首页数值。
- 关键容器和网格使用本规格的 `54 / 48 / 40 / 24 / 20 / 18 / 14` 适配节奏。
- 图标只来自 HackerNoon Pixel Icon Library，不出现 emoji、Unicode 图标或其他图标库。
- 首屏具备 `2px` 边界、`16px` 桌面圆角与首页式表面。
- FDE 方法和服务产品分别满足 `3 / 2 / 1` 响应式列数。
- 黑色信息卡、薄荷青绿高亮和浅色内容表面的职责不混用。
- 存在 `prefers-reduced-motion` 降级。
- 定制样式继续限定在 `.wbx-service` 或 `.custom-service-page` 下，不污染其他页面。

### 浏览器验收

- 在 `1440px`、`900px`、`390px` 三档检查无横向溢出、遮挡、裁切或不合理空白。
- 检查浅色与深色主题的文字、边界、高亮和二维码容器对比度。
- 检查键盘焦点、禁用状态、锚点跳转和 hover 反馈。
- 与首页并排观察时，确认强调色、黑色、页面底色、描边、圆角和像素图标属于同一套视觉系统。

## 验收标准

- 页面第一屏明确继承首页视觉语言，但不重复首页内容。
- 字体家族、品牌色、像素图标和交互气质与首页同源，字号、字重、间距和模块结构不做一比一复刻。
- 所有强调色来自 `var(--wbx-accent)`，不存在错误的黄绿色主色。
- 现有服务业务事实、价格、路径、规则和二维码状态无变化。
- FDE 六宫格和服务产品目录满足 `3 / 2 / 1` 响应式合同。
- 页面无卡片套卡片、无重复事实、无重复编号、无虚假入口。
- 相关自动化测试、链接检查、资源检查和生产构建通过。
- 本地预览完成，未部署。
