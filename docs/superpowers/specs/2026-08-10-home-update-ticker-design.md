# 首页内容更新滚动通知设计

## 目标

在首页 Hero 左侧内容区顶部增加一条内容更新通知带，持续展示最近的站内内容更新，并为每条更新提供可点击的站内入口。通知带延续现有黑白像素风，不改变 Hero 主标题、按钮、图标组合和价值条。

## 内容来源

新增独立的 `homeUpdates.ts` 数据模块。每条记录包含：

- `date`：`YYYY-MM-DD` 格式的发布日期；
- `title`：面向读者的简短更新说明；
- `href`：站内目标路径。

首页在渲染前按日期倒序排列。更新内容由编辑者显式维护，不使用 Git 提交时间，也不依赖运行时接口。首批内容覆盖第二篇内容校正、旧版链接兼容和本次站点内容治理更新。

## 布局与视觉

- 通知带位于 `.wbx-hero__copy` 内，排在 `27 CHAPTERS / 4 PARTS / ∞ WORKFLOWS` 标签之前，占满左侧文案列。
- 外观为白底、2px 黑色边框、直角结构，与首页按钮和像素视觉语言一致。
- 左侧固定区域显示提示图标与 `内容更新`，使用黑底白字，保持稳定宽度。
- 右侧为单行裁切轨道，内容由右向左无缝循环；每条由日期、标题和分隔符组成。
- 链接继承黑色文字，悬停或键盘聚焦时使用绿色底色或下划线提供明确反馈。
- 通知带高度固定，动态内容不得改变 Hero 尺寸。

## 动效与交互

- 使用纯 CSS transform 动画驱动横向循环，不使用定时器。
- 轨道渲染两份相同列表，确保首尾无缝衔接；重复副本设置为 `aria-hidden="true"`。
- 鼠标悬停、通知带内部获得键盘焦点时暂停动画，便于阅读和点击。
- 用户启用 `prefers-reduced-motion: reduce` 时禁用动画、隐藏重复列表，仅显示最新一条更新。
- 所有链接通过 VitePress `withBase()` 生成，兼容站点 base 配置。

## 响应式规则

- 桌面端通知带使用左侧固定标签和右侧滚动轨道。
- 960px 以下仍保持单行，不压缩主标题；适当缩小标签宽度、字号和间距。
- 390px 视口不得产生横向页面滚动；通知标题在轨道内保持单行并由轨道裁切。

## 可访问性

- 容器使用有意义的 `aria-label="内容更新"`，不使用会反复播报动画文本的 live region。
- 可见主列表中的每条内容保持正常链接语义；重复副本不进入辅助技术阅读顺序，也不可获得焦点。
- 键盘焦点样式必须清晰可见。

## 测试与验收

- 单元测试验证数据按日期倒序、链接经过 `withBase()`、重复副本隐藏且不可聚焦。
- CSS 契约测试验证固定高度、轨道裁切、连续动画、悬停/聚焦暂停和减少动态效果规则。
- 浏览器在 1440x900 与 390x844 验证：通知带位于指定区域、滚动正常、没有横向溢出、标题与按钮未被挤压。
- 生产构建、完整测试、链接检查继续通过。

## 非目标

- 不增加后台管理界面、RSS、远程 API 或自动读取 Git 历史。
- 不在内页、导航栏或移动菜单重复展示通知。
- 不修改首页 Hero 以外的内容结构和视觉系统。
