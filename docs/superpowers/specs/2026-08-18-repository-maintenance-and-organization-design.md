# WORKBUDDY WB-X 仓库全面整理设计

**日期：** 2026-08-18  
**状态：** 已确认，待实施计划  
**范围：** 仓库结构、依赖治理、维护资料、源码拆分、自动检查与回归验证

## 1. 背景

网站当前已与线上版本对齐，但仓库本身存在明显的长期维护负担：

- Git 跟踪约 18,836 个文件，其中约 18,220 个来自误提交的 `.pnpm-store`，工作树占用约 329 MB。
- 同时跟踪 `pnpm-lock.yaml` 与 `package-lock.json`，而项目声明和 CI 均以 pnpm 11.9.0 为准。
- 根目录缺少 README；`CONTENT_INVENTORY.md` 的日期、域名和基线信息已经过期。
- `.qoder`、`.superpowers`、`.tools`、本地 Vercel 文件、截图和审计资料的边界不清晰。
- 首页样式、图片清单生成器和首页综合测试文件过大：`home.css` 约 1,491 行，`build-image-manifest.mjs` 约 934 行，`home-hero-icons.test.ts` 约 1,018 行。
- 媒体资源体积较大，但本阶段不能以压缩、重编码或公开路径迁移的方式改变线上资源。

本设计选择“平衡整理”：解决仓库卫生和明显的源码维护热点，同时保持网站界面、功能、URL、公开资源地址和线上内容不变。

## 2. 已确认的决策

1. 不改写 Git 历史。
2. 不改变线上 URL、公开文件路径或页面行为。
3. 包含行为不变的源码拆分，但不开展视觉或业务重构。
4. 有复核价值的资料统一归档；临时文件只加入忽略和清理清单，不直接删除。
5. 依赖管理统一为 pnpm 11.9.0，当前版本移除 `package-lock.json`。
6. `.pnpm-store` 从当前 Git 索引中移除并加入忽略，但保留本机文件。
7. 现有 `stash@{0}`（`pre-live-alignment-2026-08-18`）不修改。

## 3. 目标

- 将 Git 跟踪文件数量从约 18,836 个降到约 700 个以内。
- 明确产品代码、源资产、生成资产、维护文档、审计证据和本地工具文件的边界。
- 建立唯一、可复现的 pnpm 安装和检查流程。
- 将三个明显过大的文件按职责拆分，并保持入口和外部契约稳定。
- 让本地和 CI 使用相同的完整验证命令。
- 为后续媒体优化、死代码清理和历史瘦身留下可执行清单。

## 4. 非目标

- 不使用 filter-repo、BFG 或强制推送缩小 Git 历史。
- 不删除 `.pnpm-store`、Vercel 配置、工具二进制、截图或其他现有本机文件。
- 不压缩、重编码或替换现有图片、GIF 和视频。
- 不调整页面文案、颜色、间距、动效、组件 DOM、导航或重定向。
- 不重写 `HomePage.vue`、`custom.css`、`service.css` 等仍可维护的文件。
- 不把发现的所有重复或死代码顺手修掉；这类事项进入后续优化清单。

## 5. 目标仓库边界

### 5.1 产品和发布文件

- `docs/`：VitePress 内容、主题和公开静态资源。
- `scripts/`：构建、链接、资源和仓库检查脚本。
- `tests/`：单元、源契约和回归测试。
- `.github/`：CI 与发布流程。
- 根目录配置：`package.json`、`pnpm-lock.yaml`、TypeScript/Vitest 配置等。
- 根目录源输入：`WB-X LOGO.svg`、`二维码.png`、`article-image-replacement-manifest.csv`；它们仍被资源脚本或测试使用，路径暂不改变。

### 5.2 维护文档

- 新增根目录 `README.md`，作为项目入口。
- 新增 `docs/maintenance/`，至少包含：
  - 仓库与目录职责；
  - 开发、检查和发布命令；
  - 源资产、生成资产和公开资产规则；
  - 截图及审计资料的命名、保留和清理规则；
  - 后续优化候选项。
- 保留并更新根目录 `CONTENT_INVENTORY.md`，修正线上域名、日期、基线和实际文件结构。

### 5.3 审计和历史资料

- `audit/` 只保存有复核价值的证据，并增加说明文件。
- 已有根目录截图和未跟踪审计截图按日期及主题归档，不直接删除。
- `.qoder` 中已跟踪的报告整体归档到 `audit/archive/`，随后将 `.qoder/` 作为本地工具输出忽略。
- `.superpowers/sdd` 中唯一已跟踪的报告迁移到 `docs/superpowers/reports/`；其余本地执行状态继续忽略。
- 未被代码或脚本引用的 `WB-X LOGO.png` 作为历史源资产归档，不删除。

### 5.4 本地或生成内容

以下内容不应进入 Git：

- `.pnpm-store/`
- `node_modules/` 与 `node_modules.preview-backup/`
- `.vercel/` 与 `.vercel-tmp/`
- `.tools/`
- `.qoder/`
- `.superpowers/` 本地执行状态
- VitePress cache、dist、coverage 和未归档临时截图

`.gitignore` 应按类别整理并去除重复规则。移除跟踪时优先只修改 Git 索引；本机文件保持原位，除非它被明确移动到归档目录。

## 6. 依赖与命令治理

- `packageManager` 继续固定为 `pnpm@11.9.0`。
- `pnpm-lock.yaml` 是唯一锁文件。
- 从当前版本移除 `package-lock.json`，但不改历史，也不修改包含旧版本的 stash。
- `package.json` 内部脚本不再通过 `npm` 自调用，统一使用 pnpm。
- 标准流程为：

```text
package.json + pnpm-lock.yaml
  -> pnpm install --frozen-lockfile
  -> pnpm check
  -> test + repository hygiene + links + assets + production build
```

## 7. 源码拆分设计

### 7.1 首页 CSS

`docs/.vitepress/theme/home.css` 保留为稳定入口，只按现有级联顺序导入：

1. `home/home-foundation.css`：页面骨架、可访问性辅助类和数据条。
2. `home/home-hero.css`：首屏、更新条、按钮、图标卡及官方站点入口。
3. `home/home-sections.css`：价值条、阅读路线、任务、系统、社区和页脚。
4. `home/home-responsive.css`：当前文件后半段的全部断点与 reduced-motion 覆盖。

拆分必须保持原始规则顺序，不调整选择器、声明、数值或特异性。`index.ts` 仍只导入 `home.css`。

### 7.2 图片清单生成器

`scripts/build-image-manifest.mjs` 保留为 CLI 入口，将下列纯职责迁入 `scripts/lib/image-manifest/`：

- CSV 解析与序列化；
- Markdown 媒体引用解析；
- 图片格式和尺寸读取；
- 路径边界与公开 URL 校验；
- 工作流状态保存与恢复；
- 暂存、备份和原子替换。

入口继续负责配置、遍历和总体编排。命令、输入、输出路径、排序、错误信息、退出码和原子回滚语义保持一致。

### 7.3 首页综合测试

将 `tests/home-hero-icons.test.ts` 按职责拆为：

- 更新条及计时行为；
- 首屏导航与布局；
- 阅读、任务与系统内容；
- 社区和产品页脚。

共享挂载、媒体查询桩、选择器和 CSS 读取逻辑进入 `tests/helpers/`。所有直接读取 `home.css` 的测试改用统一的样式读取器，按入口导入顺序组合样式文件；断言语义保持不变。

## 8. 仓库卫生检查

新增 `check:repo`，并纳入 `pnpm check`。检查至少覆盖：

- 禁止的本地目录没有被 Git 跟踪；
- 只存在 `pnpm-lock.yaml` 一个包管理器锁文件；
- README、维护指南和必要源资产存在；
- 审计资料位于约定目录；
- 首页 CSS 入口和拆分文件完整、顺序固定。

检查应输出可操作的错误信息，不执行自动删除或自动修复。

GitHub Actions 继续使用 Node 24 与 pnpm 11.9.0，通过 frozen lockfile 安装，并运行与本地相同的 `pnpm check`。发布目标和部署配置不改变。

## 9. 数据安全与错误处理

- 执行前记录 `git status`、未跟踪文件清单、stash 名称及 stash 路径清单。
- `.pnpm-store`、`.tools` 等采用“停止跟踪但保留本机文件”的方式处理，并在操作后验证目录仍存在。
- 归档使用明确的逐项移动清单，不使用宽泛 glob 或递归删除。
- 图片清单生成器继续先写临时目录，再以原子替换方式更新目标；失败时恢复原文件。
- 任一批次验证失败时停止，不在失败状态上继续下一个批次。

## 10. 实施批次与回滚

1. **基线与安全检查**：记录状态，运行现有完整检查。
2. **仓库卫生**：整理 `.gitignore`，停止跟踪缓存、工具输出和重复锁文件。
3. **资料归档**：移动审计、工具报告和历史源资产，补充索引。
4. **源码拆分**：依次拆分 CSS、图片清单脚本和首页测试；每一步运行聚焦测试。
5. **文档与 CI**：补齐 README、维护指南、内容清单和仓库检查。
6. **最终回归**：运行全部检查、构建及浏览器验证。

每类整理使用独立提交。若出现回归，只回退对应提交；不需要恢复其他已通过的批次。

## 11. 验证方案

### 11.1 自动验证

- 每次结构拆分运行对应聚焦测试。
- 图片清单生成器拆分前后比较生成内容和错误路径。
- 最终运行 `pnpm check`，要求单元测试、仓库卫生、链接、资源和生产构建全部通过。
- 检查构建产物中的路由、重定向和公开资源路径没有变化。

### 11.2 浏览器回归

在相同视口下检查本地预览的：

- `/`
- `/wb-x/`
- `/resources/`
- `/help/`
- `/wb-x/reading-guide/`

至少覆盖桌面和移动端，确认无视觉偏差、横向溢出、失效导航或控制台错误。自动构建和链接检查覆盖其余内容页。

### 11.3 Git 与文件验证

- 跟踪文件约 700 个以内。
- 禁止目录不再出现在 `git ls-files`。
- 本机 `.pnpm-store` 和工具文件仍存在。
- 整理前的未跟踪资料要么仍在本机，要么有明确归档去向。
- `stash@{0}` 名称和七个已记录路径保持不变。
- 最终工作树没有意外的已跟踪改动。

## 12. 验收标准

当且仅当以下条件全部满足，整理才算完成：

- 仓库边界、pnpm 单一依赖流程和维护文档已经落地。
- 三个维护热点完成行为不变的职责拆分。
- 缓存和本地工具内容不再被 Git 跟踪，且本机副本没有被删除。
- 所有自动检查和生产构建通过。
- 关键页面桌面、移动端回归通过。
- 网站 URL、公开资源路径、内容、视觉和交互行为未改变。
- 现有 stash 和用户未跟踪资料得到保留或明确归档。

## 13. 后续独立优化项

以下事项仅记录，不属于本阶段：

- 使用独立项目评估 Git 历史瘦身。
- 对大图片、GIF 和视频做感知质量评估、压缩与缓存策略设计。
- 识别并删除确认无用的代码或资源。
- 继续拆分 `custom.css`、`service.css` 或 Vue 页面组件。
- 建立性能、可访问性和 SEO 的量化基线。
