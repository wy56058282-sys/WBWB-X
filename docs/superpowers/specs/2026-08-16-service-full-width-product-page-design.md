# 定制服务通栏产品展示页设计

## 状态

- 日期：2026-08-16
- 状态：设计已确认，待书面规格复核
- 适用页面：`/help/`
- 调整范围：重构定制服务页面的信息架构与视觉层级，移除右侧固定目录，改为通栏产品与服务展示。

## 背景

当前定制服务页面在多轮内容补充后出现以下问题：

1. 需求诊断、FDE 方法、服务价格、企业采购、适用问题、流程和规则被拆成大量同权重模块，阅读主线不清晰。
2. 右侧固定目录占用有效宽度，却没有承担关键转化任务，主内容因此显得拥挤。
3. 多组编号、重复入口和近义说明同时出现，用户难以判断哪些是服务、哪些是方法、哪些是办理步骤。
4. 列表顶部装饰线和区块分割线过多，与网站其他页面的视觉语言不一致。
5. 桌面端信息密度过高，移动端容易出现标题、价格、二维码和列表彼此割裂或拥挤的问题。

## 目标

将 `/help/` 重构为一条连续的服务决策路径，使用户能够依次完成：

1. 理解服务定位。
2. 判断当前问题属于哪一类。
3. 了解可购买的服务和价格。
4. 区分企业版席位采购与专业服务费用。
5. 确认适用条件、交付结果和服务边界。
6. 选择咨询或报名入口。

页面应更像产品与服务目录，而不是带目录导航的长篇文档。

## 已确认决策

1. 删除右侧固定目录及其占位宽度，页面采用居中通栏布局。
2. 保留现有已确认的服务类型、价格、办理流程、规则和隐私边界。
3. 允许合并同义说明、重复编号、重复按钮和重复入口，但不得新增未经确认的价格、承诺或权益。
4. 商务微信、企业采购渠道二维码和服务付款属于三条独立路径，不得混用。
5. 页面以服务产品为主，FDE 方法论用于解释服务能力，不作为独立长文抢占主层级。
6. 删除无信息价值的装饰性粗分割线；需要区分模块时使用留白、背景层或细边界。

## 页面信息架构

### 1. 首屏：需求诊断

首屏承担定位和首次转化，包含：

- 主标题：`WorkBuddy 需求诊断`
- 一句服务价值说明。
- 主按钮：`开始需求沟通`
- 需求诊断价格、时长和固定交付摘要。
- 商务微信二维码或未开放占位。

价格、时长和固定交付只保留一处。现有类似 `¥399 · 45 分钟 · 固定诊断结论摘要` 的重复摘要在价格信息已完整呈现时删除。

### 2. 问题与方法：从工具采购到业务落地

该区域解释为什么需要专业服务，并按三个层级展开：

- 三类典型问题：不会用、跑不通、管不住。
- 三层服务能力：WorkBuddy 入门培训、业务场景陪跑、AI 资产治理。
- 五步实施方法：岗位任务梳理、首批场景筛选、配置与开发、测试与上线、推广与运营。

三组内容必须各自拥有清晰标题和独立留白，不能压缩成一个连续的信息矩阵。每组内部只使用一套编号，编号不得由浏览器列表序号与视觉编号重复生成。

### 3. 服务产品目录

集中展示五类服务：

1. 需求诊断。
2. 定制培训。
3. FDE 现场支持。
4. 项目实施。
5. 持续支持。

每项至少包含名称、价格或计价方式、时长或服务周期、适用场景和核心交付。使用现有已确认数据，不在本次设计中修改价格。

桌面端优先采用三列产品网格；平板端两列；移动端单列。产品项是独立卡片或清晰列表项，不在外层再套装饰性卡片。

### 4. 企业版采购

企业版采购与专业服务分开说明，包含：

- 企业版席位采购前置条件与费用边界。
- 专属腾讯云企业采购渠道二维码。
- 席位费由腾讯云或 WorkBuddy 工具侧收取，本站不代收。
- 20 席及以上权益只使用已经确认的现有文案，不额外扩大承诺。

企业采购二维码不得替代商务微信、需求诊断报名或服务付款入口。

### 5. 适用问题与诊断输出

将“适合带着这些问题来”和“诊断输出”作为同一决策区的两个并列模块：

- 左侧帮助用户判断是否适合咨询。
- 右侧明确需求边界、可行性判断、建议交付物、预估周期、关键风险和后续建议。

内容保持完整，但删除与前文重复的说明句。

### 6. 沟通、报名与服务流程

使用一套连续编号说明：

1. 提交需求。
2. 确认范围与时间。
3. 填写企业微信报名表。
4. 发送付款二维码。
5. 完成诊断。
6. 收到结论并选择下一步。

流程步骤不得显示双重编号，不在每个步骤顶部增加粗横线。报名表未准备好时显示明确的不可用状态，不渲染虚假链接。

### 7. 服务规则与边界

页面末尾集中呈现：

- 退款边界。
- 服务范围。
- 隐私与资料保存边界。
- 真实交付结果和不包含内容。

规则使用简洁分组或定义列表，不重复前文产品卡片中的营销说明。

## 视觉系统

### 布局

- 移除右侧固定目录、粘性目录和对应网格轨道。
- 主内容沿用指南页面的居中基线，最大内容宽度以现有指南页容器为准，目标约 `1104px`。
- 大区块使用通栏纵向节奏；区块内部按内容需要使用两列或三列。
- 页面左右留白、首屏起始位置和导航下方间距与指南页保持一致。

### 层级

- H1、H2、正文和辅助信息沿用指南页字号与字重层级。
- 荧光绿只用于主按钮、状态、编号和关键强调。
- 黑色描边用于明确操作和必要边界，不把所有内容都框成卡片。
- 卡片圆角不超过 `8px`。
- 不使用粗横线作为通用分隔；以 `48px` 左右的区块间距、轻背景和细边界建立节奏。
- 不使用卡片嵌套卡片。

### 编号

- 每个模块内部只允许一套编号来源。
- 自定义视觉编号时，列表本身必须清除默认 marker。
- 不显示 `1. 01`、`2. 02` 等重复编号。

### 二维码

- 商务微信与企业采购二维码分别标注用途。
- 二维码保持正方形、完整静区和可扫描尺寸，不裁切、不拉伸。
- 占位状态不得看起来像可点击或可扫描的真实二维码。

## 响应式设计

### 桌面端

- 页面为单一通栏主轴，无右侧目录。
- 产品目录和适用内容可使用三列。
- 首屏可将服务说明与价格、二维码组合成平衡的两列结构。

### 平板端

- 双列内容改为等宽或主次两列，产品目录使用两列。
- 二维码与说明保持在同一语义模块内，不漂浮到无关内容旁。

### 移动端

- 所有内容按阅读顺序单列堆叠。
- H1、价格、按钮和二维码不得裁切、重叠或超出视口。
- 产品卡片、流程和规则占满可用宽度。
- 不依赖横向滚动查看服务价格或步骤。

建议断点合同：

- `>= 1024px`：最多三列。
- `641px - 1023px`：最多两列。
- `<= 640px`：单列。

## 交互与可访问性

- 主按钮跳转到真实可用的咨询或申请区。
- 所有链接、按钮和可交互控件提供高对比度 `:focus-visible` 状态。
- 禁用入口使用语义化禁用状态，不使用可点击样式。
- 二维码配有可见用途说明和准确替代文本。
- 页面标题结构按 H1、H2、H3 顺序组织，不用视觉字号模拟标题。
- 深浅主题下文字、边界、按钮和二维码容器均保持清晰对比。

## 验收标准

### 内容与功能

- 右侧固定目录及其占位宽度完全移除。
- 五类服务、现有价格、企业采购、适用问题、诊断输出、流程和规则均可找到。
- 不出现重复编号、重复价格摘要、重复 CTA 或同义标题。
- 商务微信、企业采购和服务付款路径清楚分离。
- 未开放的报名或支付入口不产生虚假跳转。

### 视觉与响应式

- `1440px`、`900px` 和 `390px` 三档均无横向溢出、文字裁切、内容重叠或布局跳动。
- 页面主轴、内容宽度、标题层级和区块节奏与指南页一致。
- 问题、三层服务和五步方法之间存在清晰留白，不再挤成一个信息墙。
- 页面不出现用于装饰的粗横向分割线。
- 产品目录在桌面、平板、手机分别呈现合理的三列、两列、单列布局。
- 二维码在三档宽度下均可完整显示并保持可扫描。

### 自动化与构建

- 组件测试覆盖页面区块顺序、CTA、二维码状态、价格和重复编号回归。
- 样式测试使用真实页面层级，覆盖三档断点、通栏宽度和目录缺失合同。
- 生产构建、内部链接、静态资源和发布边界检查通过。
- 浏览器验收覆盖浅色、深色、键盘焦点、移动端和真实二维码解码。

## 非目标

- 本次不接入支付后台、订单系统或预约系统。
- 本次不开发用户注册、登录或会员中心。
- 本次不修改百度统计、Umami 或首页数据模块。
- 本次不重新制定服务价格、FDE 权益、席位佣金或退款政策。
- 本次不改变全局导航和其他页面的信息架构。

## 实施边界

实施应优先修改定制服务组件、其专属样式、配置和对应测试。不得以全局 CSS 覆盖的方式影响案例集、指南、首页或案例详情页。当前工作树中与本规格无关的未提交改动必须原样保留。
