# 交流群二维码悬停交互设计

## 目标

将顶部导航“交流群”的二维码弹层从仅点击触发，升级为桌面端悬停可预览，同时保留点击、键盘和触屏操作。弹层视觉、二维码内容、定位算法及页面结构不变。

## 交互方案

采用“悬停预览 + 点击固定”的混合模式。

- 支持精确指针且设备具备 hover 能力时，指针进入“交流群”导航项便展示二维码。
- 指针可以从导航项移动到二维码弹层；两者都离开后延迟 180ms 关闭，以跨越触发项与弹层之间的空隙。
- 延迟期间再次进入导航项或弹层会取消关闭，避免闪烁。
- 悬停打开只展示弹层，不主动移动焦点。
- 点击导航项会将弹层固定为打开状态；固定后移出不关闭，点击外部、再次点击导航项、关闭按钮或按 Escape 才关闭。
- 键盘聚焦“交流群”后按 Enter 或 Space 继续使用点击固定流程，弹层获得焦点并保留现有焦点循环和 Escape 关闭能力。
- 触屏或不支持 hover 的设备只使用现有点击流程，不监听模拟悬停。

## 状态模型

弹层区分三种状态：

1. `closed`：未展示。
2. `preview`：由桌面悬停打开，不抢焦点，可在触发项与弹层之间移动。
3. `pinned`：由点击或键盘操作打开，保持现有对话框焦点和关闭语义。

从 `preview` 点击同一触发项时转为 `pinned`，不会先关闭再重开。关闭后清理活动触发项、延迟计时器和固定状态。只有 `pinned` 关闭时才将焦点恢复到触发项；纯悬停预览不改变焦点。

## 组件边界

- `Layout.vue` 继续负责识别所有指向 `#community` 的 VitePress 桌面与移动导航链接，并增加委托式 pointer/focus 触发。
- `CommunityQr.vue` 负责弹层状态、延迟关闭、固定状态、焦点管理及弹层自身的 pointer 进入/离开。
- 全局公开入口应明确区分预览打开与固定打开，避免用同一个“再次调用即切换”的接口承载两种语义。
- `community-popover-position` 保持不变，弹层仍锚定当前触发项并响应滚动与窗口尺寸变化。

## 可访问性

- “交流群”仍是可点击链接，现有导航语义不变。
- 悬停预览不抢夺键盘焦点，也不增加 live region。
- 固定打开继续使用带标题和说明的 `role="dialog"`、焦点循环、Escape 关闭和焦点恢复。
- 关闭按钮保留，鼠标和键盘均可操作。
- reduced motion 不需要额外分支，因为本次不新增位移动画或淡入动画。

## 异常与边界

- 快速经过导航项：180ms 延迟只用于关闭，打开不延迟，保证反馈直接。
- 导航响应式重排或页面滚动：弹层沿用现有重新定位逻辑。
- 页面上存在多个 `#community` 链接：活动触发项始终更新为最近操作的链接。
- 弹层打开期间触发项从 DOM 移除：关闭时先检查元素仍连接到文档，再尝试恢复焦点。
- 组件卸载时必须清理文档监听器和关闭计时器。

## 验收标准

- 桌面端悬停导航项立即出现二维码，移入弹层不关闭；完全移出后约 180ms 关闭。
- 悬停预览期间焦点保持在原位置。
- 点击可固定弹层，移出后仍保持；外部点击、再次点击、关闭按钮和 Escape 均能关闭。
- 键盘打开后焦点进入弹层，Tab 循环和焦点恢复正常。
- 触屏设备点击行为与当前版本一致，不因模拟 hover 发生开关两次。
- 桌面菜单和移动菜单中的“交流群”链接均可用。
- 既有锚定位置、滚动更新、二维码资源及无背景滚动锁定行为不回归。

## 测试范围

- 组件测试覆盖 `preview` 与 `pinned` 状态转换、180ms 延迟取消、焦点是否移动、关闭与恢复焦点。
- Layout 测试覆盖桌面 hover 能力判断、事件委托、移动端点击回退及嵌套文字节点触发。
- 保留现有弹层定位、外部点击、关闭按钮、Escape、焦点循环和二维码资源断言。
- 生产预览在桌面与移动视口验证悬停、点击、键盘、触屏回退及弹层不闪烁。
